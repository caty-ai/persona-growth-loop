# 証拠定義 v1 — 遅延報酬の判定規則（凍結）

> Status: **FROZEN**（pgl#4 lane #0）。実装先 = ハーベスター+夜間集計（pgl#6）・鏡（pgl#7）。
> 原則: **即時センチメントでは学習しない**。遅延シグナルのみが人格に触れる。
> 数値は config（`config/evidence.yml`）で可変と明記したもの以外、変更に S/M quorum レビューを要する。
> **config 可変値も、緩和方向（採用・露出を容易にする変更）は council + オーナー承認を要する
> （governance-R12a guardrail-loosening 条項・CP-2 整合 2026-08-02）。厳格化のみレビュー不要。
> 緩和か強化か争いがある場合は緩和扱い。**

## 1. 候補化（observation → candidate）

| 条件 | 値 | 可変 |
|---|---|---|
| 窓 | 直近 **30日** | config |
| 出現回数 | **≥ 8回** | config |
| 日分散 | **≥ 5日**に分散 | config |
| 対象 | Tier L の候補化対象断片（speaker スコープ内・240字以下・observation-log-schema §2） | 固定 |
| 除外 | blocklist 掲載（過去 blocked と正規化同形含む）/ guard lint reject（overlay-contract §2） | 固定 |

- 本表の config 可変値の**緩和方向**（窓の拡大・回数/日分散の引き下げ等）は council + オーナー承認を
  要する（ヘッダ注記=governance-R12a guardrail-loosening 条項）。厳格化のみレビュー不要。
- 候補化は**機械抽出のみ**（頻度・分散）。writer の趣味・推測で候補を増やさない。
- 1夜の新規 candidates ≤ 3（overlay-contract §12 と同値・二重定義はしない — 正はあちら）。

## 2. 試用注入（稀少制約付き）

用語（overlay-contract §1 の state→render 対応が正）: 「candidates の試用注入」とは
**staged 状態の phrase が render 面 `candidates.txt` に掲載されて注入される**ことを指す。
「検疫 = 非注入」ではない。台帳 state `candidate` は render 未掲載（初回掲載 = §5.2 diff レビュー通過後）。

| 制約 | 値 | 強制方式 |
|---|---|---|
| 1セッションあたり | **≤ 1回** | **検出的**: render 固定テンプレのプロンプト指示（「稀に・1セッション1回まで」）+ 使用ログで実測検証。違反率は鏡週次の観測対象 |
| 掲載日 | **日次 render トグルで掲載日 ≈50%**（§3 holdout と同一機構・決定論） | **構造的**: 非掲載日は render に存在しない = 使えない |
| 同時試用 phrase 数 | ≤ 3個 / 面（掲載上限 12 entries とは別） | **構造的**: applier が `staged_at` 昇順の先頭3個のみを日次トグル対象にする（決定論ローテーション: 先頭が adopted/降格で抜けたら次繰り上げ） |

## 3. holdout（昇格判定の対照群・**日次 render トグル方式**）

- **機構（構造的強制）**: staged phrase は**日単位**で render に載る/載らないを切り替える。
  割当は決定論: `sha256(face + phrase_id + date) の最終バイトの偶奇`（乱数不可・再現可能）。
  掲載日 ≈50% = 「適格機会の 50% のみ使用」の実現形。render は夜間にのみ変わるため
  SPEC §5 のバイト安定性（モード不変のあいだ同一）と両立し、セッション内変動を要しない。
  夜間トグルによる prompt cache 無効化は受容済み（overlay-contract §4）
- **群の定義**: 露出日群 = 掲載日の適格セッション / holdout 日群 = 非掲載日の適格セッション。
  適格セッション = 当該面がアクティブな Tier L 収集対象セッション
- **非劣後の v1 定義**（小標本の正直な運用・統計検定はしない）:
  - 露出日群の負シグナル件数 ≤ holdout 日群 かつ
  - 露出日群の事後明示言及件数 ≥ holdout 日群
  （観測 schema が捕捉できる2系列のみで定義する。「解決系の完遂率」等の追加 metric は
  観測ソースを定義できた時点で本契約の改定として導入）
- カウンタは台帳 `holdout.{exposed_days, holdout_days, exposed_neg, holdout_neg, exposed_mentions,
  holdout_mentions}`（overlay-contract §1.1）。夜間集計が Tier L + 使用ログから日付で振り分ける
- **正直な限界**: 非掲載日でもモデルが会話履歴・記憶経由で phrase を使う可能性はゼロでない。
  使用ログが非掲載日の使用を検知した場合、当該セッションは露出日群として数える（protocol 逸脱を
  隠さず露出側に倒す）。逸脱率は鏡週次の観測対象
- **ルカ面の帰属条件（P1 の契約語化 — 改定 #47・設計 = docs/luca-lane-v1.md §3.1・レビュー Grok M5）**:
  ルカ面の exposed/holdout 計数は、**当夜の本番搬送（overlay-contract §5.3 e2）の成功、または
  差分なしにより e2 が不要で当夜の g0 reconciliation が一致（GREEN）であることを伴う render 状態に
  のみ帰属する**。e2 失敗・skip の夜が明けた日は、いずれの群にも計数しない
  （本番に届いていない render 状態への帰属は日次帰属の嘘になるため — P1。差分なし夜は直近の
  e2 成功状態が本番で継続していることを毎夜の g0 が検証済みのため計数する — 差分なし夜を
  落とすと k=1 の staged では夜の約半数が帰属から消え、標本が「前夜トグルが反転した日」に
  条件付けられた偏りを持つ — #47 delta・Opus M5）
- **露出日の 04:30 アンカー（ルカ面 — 改定 #47・レビュー Fable m4/Opus F36）**: 露出日 =
  render_date（JST）とし、**当日 04:30 以降の会話に適用する**（本番搬送の restart 窓 04:00–04:30 の
  完了後）。00:00–04:00 の会話は前夜 render 下 — v1 受容の帰属ノイズとして明記する

## 4. シグナル定義

| シグナル | 定義 | 扱い |
|---|---|---|
| **事後の明示的言及**（主たる正） | 使用より**後の** user 発話に、phrase または当該表現様式への肯定的言及（「その言い方いいね」「〇〇って言うの好き」等） | 昇格の必須条件の一つ。検出はパターン + 夜間 LLM 分類の二段。判定不能は**言及なし側**に倒す |
| **負シグナル**（明示拒否） | user 発話が (a) phrase を引用して、または (b) 直前 assistant 発話が adopted/staged phrase を使用した直後に、拒否語彙（やめて / 言わないで / 変 / 気持ち悪い / らしくない / 真似しないで 等の列挙 + 夜間分類）を含む | **1件で即降格 + blocklist**（unlearn 経路 = overlay-contract §15）。誤検知の復帰はオーナー承認のみ（安全側非対称） |
| 翌日再訪・ラリー継続 | エンゲージメント系 | **弱い補助のみ**。単独では昇格根拠にならない（同調バイアス対策・裁定 F-6） |
| その場の「ありがとう」・即時ポジ反応 | 即時センチメント | **学習に使わない**（迎合の主経路） |

## 5. 昇格（candidate → staged → adopted）

```
candidate → staged:  §1 充足 + guard lint 通過 + 異種モデル diff レビュー通過（自動・夜間）
staged   → adopted:  以下【全て】を充足（AND）
  - staged 経過 ≥ 14日
  - 実使用 ≥ 3回（使用ログ実測）
  - holdout 非劣後（§3）
  - 負シグナル = 0
  - 事後の明示的言及 ≥ 1
```

- 昇格は 1夜 ≤ 2 phrase（overlay-contract §12）。条件充足でも急がない（人格の変化速度そのものを絞る）。
- adopted からの**降格**: 負シグナル1件で降格（→ blocked）。**自動 = 次の夜間サイクルで実行・
  手動 `bin/pgl-block` = 即時**（overlay-contract §15 と同一の時定性）。
  また 90日間 使用実測 0 なら demoted（判定源 = 台帳 `evidence.last_used_at`。使用ログは30日 prune のため
  台帳が持つ。自然風化 — blocklist ではないため再候補化可・config）。

## 6. レーン metric（R11 のレーン単位充足）

overlay レーンは R11（効果測定つき採用）を**レーン単位**で満たす。事前宣言する metric:

| metric | 基準 | 測定 |
|---|---|---|
| 明示負シグナル率 | **< 5%**（露出ベース・30日窓） | 夜間集計 |
| holdout 非劣後 | 維持（§3 定義） | 夜間集計 |
| 効果報告 | **鏡レポート（週次ライト+月次ディープ）を R11 の効果報告に指定** | pgl#7 |

- **未達 → レーン降格**: candidates 試用注入を停止（adopted は維持・freeze 相当）。
  復帰は原因分析 + オーナーダイジェストでの報告 + **オーナーの決定**後（governance-R11 alignment・CP-2 整合 2026-08-02）。
- 鏡の比較対象は **build/ 実注入バイト**（ソースではない・裁定 E-3）。
- 固定 eval probe（~20件・押し戻しが正解のホールドアウト・別モデル採点・迎合方向の合意率上昇で
  自動 HOLD 提案 + 赤旗）は鏡 v1（pgl#7）の受け入れ条件。**鏡 v1 稼働は CP-3 の前提**。
- 鏡週次ライトの構成要素は「採用サマリ・**対立性スコア**・soul ハッシュ照合」（裁定 F-5）。
  対立性スコアの定義の家 = **pgl#7**（eval probe 系の押し戻し維持度 metric として凍結する）。
  週次ライト本文は**オーナー限定置き場**（phrase 本文を含みうるため）・Tier S へは
  observation-log-schema §5 の集計値のみ。

## 7. 観測信頼度（fast path 汚染の監視）

リアルタイム層（fast path）は自己学習しないが、観測ログを経由した間接影響は理論上ありうる。
鏡の月次ディープに「候補化された phrase の出所分布」（自発 user 発話か・assistant 使用直後の
オウム返しか）を含め、オウム返し比率が高い phrase は昇格対象から除外する（config: echo_ratio > 0.5）。
